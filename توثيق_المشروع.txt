1. نظرة عامة على المشروع
-----------------------------------------------------------------------

الاسم    : نظام التوجيه الأكاديمي الذكي
الإصدار  : 2.0
اللغة    : Python 3
المكتبات : customtkinter (واجهة المستخدم)
الملفات  : main.py (الواجهة) + logic.py (المنطق والذكاء)

الهدف من المشروع:
    مساعدة الطالب أو الشخص على اتخاذ قرار مهني صحيح عبر طريقتين:
    - إما أن يدخل مهاراته فيحصل على التخصصات المناسبة له
    - أو أن يدخل التخصص الذي يريده فيحصل على خارطة الطريق الكاملة

2. هيكل المشروع
-----------------------------------------------------------------------

am/
├── main.py     ← واجهة المستخدم الرسومية (GUI)
└── logic.py    ← محرك الاستدلال والذكاء الاصطناعي

التقسيم المعتمد هو نمط MVC مبسّط:
    - logic.py  = Model  (البيانات والمنطق)
    - main.py   = View + Controller (العرض والتحكم)

الكلاس الرئيسي: AcademicInferenceEngine

[ 3.1 ] قاعدة المعرفة (Knowledge Base)
---------------------------------------
    النوع    : Dictionary (قاموس متداخل)
    العدد    : 8 تخصصات
    البنية لكل تخصص:
        {
            "اسم التخصص": {
                "skills"   : قائمة المهارات المطلوبة,
                "roadmap"  : خطوات المسار بالترتيب,
                "cost"     : قيمة الصعوبة (0-100),
                "emoji"    : رمز تعبيري,
                "desc"     : وصف مختصر,
                "duration" : المدة التقديرية,
                "salary"   : الراتب المتوقع
            }
        }

    التخصصات الثمانية:
    ┌─────────────────────────┬──────────────────────────────────────┬────────┐
    │ التخصص                  │ المهارات                              │ صعوبة │
    ├─────────────────────────┼──────────────────────────────────────┼────────┤
    │ خبير ذكاء اصطناعي      │ برمجة، رياضيات، بيانات، إحصاء، ML   │  90   │
    │ مهندس أمن سيبراني       │ شبكات، تشفير، لينكس، برمجة، اختراق  │  75   │
    │ محلل بيانات ضخمة        │ إحصاء، قواعد بيانات، رياضيات، تحليل │  65   │
    │ مطور تطبيقات موبايل     │ برمجة، تصميم، جافا، سويفت، UI       │  60   │
    │ مهندس حوسبة سحابية      │ شبكات، برمجة، لينكس، DB، DevOps     │  80   │
    │ مصمم UX/UI              │ تصميم، إبداع، UI، فوتوشوب، UX       │  50   │
    │ مطور ويب متكامل         │ برمجة، HTML، CSS، JS، قواعد بيانات  │  55   │
    │ مهندس روبوتات           │ رياضيات، برمجة، إلكترونيات، ميكانيكا│  95   │
    └─────────────────────────┴──────────────────────────────────────┴────────┘

[ 3.2 ] جدول المرادفات (Skills Aliases)
-----------------------------------------
    النوع    : Dictionary
    الهدف    : تحويل المدخلات الإنجليزية أو العامية إلى المصطلح الرسمي
    أمثلة   :
        "python"  → "برمجة"
        "sql"     → "قواعد بيانات"
        "linux"   → "لينكس"
        "ai"      → "تعلم الآلة"
        "figma"   → "تصميم"
        "hack"    → "اختبار اختراق"
    الفائدة  : يجعل النظام مرناً ويقبل مدخلات متنوعة

4. الخوارزميات المستخدمة
-----------------------------------------------------------------------

╔══════════════════════════════════════════════════════════════════════╗
║  الخوارزمية الأولى: الاستدلال الأمامي (Forward Chaining)           ║
╚══════════════════════════════════════════════════════════════════════╝

    التعريف:
        أسلوب استدلال في الأنظمة الخبيرة يبدأ من الحقائق المعروفة
        (المهارات) ويستنتج منها النتائج (التخصصات المناسبة).
        يُسمى أيضاً "Data-Driven Reasoning".

    كيف يعمل في المشروع:
        1. المستخدم يدخل مهاراته: "برمجة، رياضيات، بيانات"
        2. normalize_skills() تحوّل المدخلات للمصطلح الرسمي
        3. لكل تخصص في قاعدة المعرفة:
           - يحسب التقاطع بين مهارات المستخدم ومهارات التخصص
           - إذا وُجد تقاطع → يحسب نسبة الثقة
        4. يرتب النتائج تنازلياً حسب نسبة الثقة

    معادلة نسبة الثقة (Confidence):
        نسبة الثقة = (عدد المهارات المتطابقة / إجمالي مهارات التخصص) × 100

    مثال تطبيقي:
        المدخل: برمجة، رياضيات
        التخصص: خبير ذكاء اصطناعي (5 مهارات)
        التطابق: برمجة + رياضيات = 2 مهارة
        الثقة = (2/5) × 100 = 40%

    الدالة في الكود: forward_chaining(user_skills)
    المخرج: قائمة مرتبة من (اسم التخصص، نسبة الثقة، المهارات المتطابقة)

    ─────────────────────────────────────────────────────────────────

╔══════════════════════════════════════════════════════════════════════╗
║  الخوارزمية الثانية: الاستدلال الخلفي (Backward Chaining)          ║
╚══════════════════════════════════════════════════════════════════════╝

    التعريف:
        أسلوب استدلال يبدأ من الهدف المطلوب (التخصص) ويعمل بشكل
        عكسي لإيجاد الشروط اللازمة لتحقيقه (المهارات والخطوات).
        يُسمى أيضاً "Goal-Driven Reasoning".

    كيف يعمل في المشروع:
        1. المستخدم يدخل التخصص: "خبير ذكاء اصطناعي"
        2. النظام يبحث عنه في قاعدة المعرفة (بحث جزئي)
        3. إذا وُجد → يعرض:
           - المهارات المطلوبة
           - خطوات المسار مرقّمة
           - المدة التقديرية
           - الراتب المتوقع
        4. إذا لم يُوجد → يقترح تخصصات مشابهة

    ميزة البحث الجزئي:
        المستخدم لا يحتاج كتابة الاسم كاملاً بالضبط
        مثال: "ذكاء" تكفي للوصول إلى "خبير ذكاء اصطناعي"

    الدالة في الكود: backward_chaining(target_career)
    المخرج: نص منسّق يحتوي المسار الكامل

    ─────────────────────────────────────────────────────────────────

╔══════════════════════════════════════════════════════════════════════╗
║  الخوارزمية الثالثة: التحليل الاستدلالي (Heuristic Analysis)       ║
╚══════════════════════════════════════════════════════════════════════╝

    التعريف:
        الـ Heuristic هي دالة تقدير تُستخدم في الذكاء الاصطناعي
        لتقييم "تكلفة" أو "صعوبة" الوصول إلى هدف معين.
        تُستخدم في خوارزميات البحث مثل A* لتوجيه القرار.

    كيف يعمل في المشروع:
        - كل تخصص له قيمة "cost" من 0 إلى 100
        - هذه القيمة تمثل مستوى الصعوبة والجهد المطلوب
        - النظام يصنّف المسار إلى 4 مستويات:

        ┌──────────────┬──────────────────────────────────────────────┐
        │ القيمة       │ التصنيف                                      │
        ├──────────────┼──────────────────────────────────────────────┤
        │ 85 - 100     │ 🔴 صعب جداً - يتطلب تفرغاً كاملاً          │
        │ 70 - 84      │ 🟠 صعب - يحتاج جهداً كبيراً                 │
        │ 55 - 69      │ 🟡 متوسط - مناسب للدراسة الجانبية           │
        │ 0  - 54      │ 🟢 سهل نسبياً - يمكن إتقانه بسرعة           │
        └──────────────┴──────────────────────────────────────────────┘

        - يعرض شريطاً بصرياً: ████████░░ (8/10)

    الدالة في الكود: heuristic_analysis(target_career)
    يظهر تلقائياً مع الاستدلال الخلفي

    ─────────────────────────────────────────────────────────────────

╔══════════════════════════════════════════════════════════════════════╗
║  الخوارزمية الرابعة: تطبيع المدخلات (Input Normalization)          ║
╚══════════════════════════════════════════════════════════════════════╝

    التعريف:
        معالجة مسبقة للمدخلات (Pre-processing) لتوحيد الصيغة
        قبل تطبيق خوارزميات الاستدلال.

    كيف يعمل:
        1. تحويل النص إلى أحرف صغيرة (lowercase)
        2. البحث في جدول المرادفات
        3. إرجاع المصطلح الرسمي أو الإبقاء على المدخل

    الدالة في الكود: normalize_skills(skills)

[ 5.1 ] البنية العامة
----------------------
    الكلاس الرئيسي: AcademicAIApp (يرث من ctk.CTk)

    المكونات:
    ┌─────────────────────────────────────────────────────────────┐
    │  Sidebar (شريط جانبي)  │         Main Area                 │
    │  ─────────────────────  │  ─────────────────────────────── │
    │  🎓 Logo                │  Header (عنوان + حالة)           │
    │  ─────────────────────  │  ─────────────────────────────── │
    │  💬 المحادثة            │                                   │
    │  🗂️ التخصصات           │     Content (4 تبويبات)          │
    │  🛠️ المهارات           │                                   │
    │  ❓ المساعدة            │                                   │
    │  ─────────────────────  │  ─────────────────────────────── │
    │  🗑️ مسح المحادثة       │  Input Area (إدخال + أزرار)      │
    └─────────────────────────────────────────────────────────────┘

[ 5.2 ] التبويبات الأربعة
--------------------------
    1. المحادثة الذكية (chat)
       - منطقة عرض الرسائل مع فقاعات للبوت والمستخدم
       - حقل إدخال مع خيار نوع الاستدلال (أمامي/خلفي)
       - مؤشر "جاري التفكير..." أثناء المعالجة

    2. استعراض التخصصات (careers)
       - بطاقات لكل تخصص تعرض: الاسم، الوصف، المدة، الراتب، المهارات
       - عرض شبكي (2 بطاقة في كل صف)

    3. قائمة المهارات (skills)
       - عرض جميع المهارات المدعومة كـ chips
       - تلميح بإمكانية الكتابة بالإنجليزية

    4. كيفية الاستخدام (help)
       - شرح مفصّل لكل خوارزمية مع أمثلة

[ 5.3 ] نظام الخيوط (Threading)
---------------------------------
    المشكلة: عمليات الذكاء الاصطناعي قد تستغرق وقتاً فتجمّد الواجهة
    الحل   : تشغيل المنطق في خيط منفصل (daemon thread)

    التسلسل:
        المستخدم يضغط إرسال
            ↓
        _run_ai() → يشغّل خيط جديد
            ↓
        _logic_thread() → يعالج في الخلفية
            ↓
        self.after(0, ...) → يُعيد النتيجة للواجهة بأمان

6. تدفق البيانات الكامل
-----------------------------------------------------------------------

    [ الاستدلال الأمامي ]

    المستخدم يكتب: "برمجة، رياضيات"
            ↓
    _run_ai() تقرأ النص وتحدد mode="forward"
            ↓
    _logic_thread() تقسّم النص: ["برمجة", "رياضيات"]
            ↓
    normalize_skills() تطبّع: ["برمجة", "رياضيات"]
            ↓
    forward_chaining() تحسب التقاطع مع كل تخصص
            ↓
    ترتيب النتائج تنازلياً حسب الثقة
            ↓
    تنسيق الرد مع شريط التقدم البصري
            ↓
    عرض الرد في فقاعة المحادثة

    ─────────────────────────────────────────────────────────────────

    [ الاستدلال الخلفي ]

    المستخدم يكتب: "ذكاء اصطناعي"
            ↓
    _run_ai() تحدد mode="backward"
            ↓
    backward_chaining() تبحث جزئياً في قاعدة المعرفة
            ↓
    تجد: "خبير ذكاء اصطناعي"
            ↓
    تُرجع: المهارات + خطوات المسار + المدة + الراتب
            ↓
    heuristic_analysis() تحسب مستوى الصعوبة (90/100)
            ↓
    تُضيف: شريط بصري + تصنيف "🔴 صعب جداً"
            ↓
    عرض الرد الكامل في فقاعة المحادثة

7. نقاط القوة في المشروع
-----------------------------------------------------------------------

    ✅ 3 خوارزميات استدلال مختلفة في نظام واحد
    ✅ عرض بصري لنسب الثقة والصعوبة


-----------------------------------------------------------------------
8. المصطلحات التقنية للمناقشة
-----------------------------------------------------------------------

    Expert System      : نظام خبير - برنامج يحاكي قرارات الخبير البشري
    Knowledge Base     : قاعدة المعرفة - مخزن الحقائق والقواعد
    Inference Engine   : محرك الاستدلال - الجزء الذي يطبق المنطق
    Forward Chaining   : استدلال أمامي - من البيانات إلى النتيجة
    Backward Chaining  : استدلال خلفي - من الهدف إلى المتطلبات
    Heuristic          : دالة استدلالية - تقدير تكلفة الوصول للهدف
    Confidence Score   : نسبة الثقة - مدى تطابق المدخل مع القاعدة
    Normalization      : تطبيع - توحيد صيغة المدخلات
    Threading          : تعدد الخيوط - تشغيل مهام متوازية
    RTL                : Right-To-Left - اتجاه النص من اليمين لليسار

9. أسئلة متوقعة في المناقشة وإجاباتها
-----------------------------------------------------------------------

    س: ما الفرق بين الاستدلال الأمامي والخلفي؟
    ج: الأمامي يبدأ من المعطيات (مهاراتك) ليصل للهدف (التخصص).
       الخلفي يبدأ من الهدف (التخصص) ليحدد المتطلبات (المهارات).

    س: لماذا استخدمت Heuristic؟
    ج: لتقييم صعوبة كل مسار وتوجيه المستخدم نحو الخيار الأنسب له
       بناءً على وقته وإمكانياته، وهو مبدأ أساسي في خوارزميات البحث
       الذكي مثل A*.

    س: كيف يتعامل النظام مع المدخلات الخاطئة؟
    ج: عبر normalize_skills() التي تحوّل المرادفات والإنجليزية
       للمصطلح الرسمي، وعبر البحث الجزئي في backward_chaining.

    س: لماذا استخدمت Threading؟
    ج: لأن واجهة tkinter تعمل في خيط واحد، وإذا نفّذنا المنطق
       في نفس الخيط ستتجمد الواجهة. الحل هو تشغيل المنطق في
       خيط منفصل وإرجاع النتيجة بـ self.after().

    س: ما نوع قاعدة المعرفة المستخدمة؟
    ج: قاعدة معرفة قائمة على القواعد (Rule-Based Knowledge Base)
       مخزّنة كـ Dictionary في Python، حيث كل تخصص يمثّل قاعدة
       تحتوي شروطها (المهارات) ونتائجها (المسار).
